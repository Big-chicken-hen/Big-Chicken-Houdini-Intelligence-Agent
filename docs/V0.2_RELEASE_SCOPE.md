# v0.2.0 release scope

This document separates current code, required follow-up work, live acceptance, and
release operations. Passing unit tests is not a substitute for the listed live checks.

## 1. Draft PR #2 baseline

Draft PR #2 restores the runtime baseline without reintroducing generic recovery or
workflow machinery:

- pinned Codex app-server `web_search = live` for ordinary and all five project roles;
- explicit native search versus explicit public-URL `openPage`, with no hidden switch;
- Launcher-generated, project-verified Qwen environment propagation through Bridge to
  HIA MCP and the knowledge CLI;
- explicit import/refresh, resumable vector build, signature-aware status, and strict
  lexical versus hybrid/vector behavior;
- a single viewport capture implementation, `SceneViewer.flipbook`, writing only below
  `.runtime/cache/screenshots`;
- removal of Stop-triggered app-server restart residue;
- five native project roles, Execution sole-writer permissions, and optional native
  read-only subagents for the other four roles when a model truly supports them.

The current baseline must stop after Python 3.10/3.11/3.13 CI, an ordinary real Turn,
five-role atomic creation, real ordinary/read-only web-search events, and the minimal
Houdini screenshot acceptance below. It does not implement the three follow-up PRs.

## 2. Three required follow-up PRs

### PR A: Supervisor Native Goal mirror

Project lifecycle remains the only execution authority. Project creation creates one
Supervisor Native Goal only as a one-way objective and status mirror. The Goal never
schedules role Turns. Goal creation failure fails project creation and precisely cleans
the just-created project members; later update failure is visible. `_hold_native_goal`,
Goal recovery, and Goal replay remain prohibited.

### PR B: unified third-compaction Thread rotation

One implementation serves ordinary Threads and each of the five project-role Threads.
It counts only native automatic compaction events, triggers exactly on the third event,
and waits until the Thread is idle. It forks once, validates complete context, Thread
source, role, model, effort, service tier, sandbox, permissions, project association,
and any Native Goal link, atomically replaces the unique identity reference, and only
then deletes the superseded Thread. Failure leaves the old Thread unchanged. There is
no automatic retry, Bridge-restart recovery, local summary, persisted chat body, or
separate ordinary/project transfer implementation. Internal subagents are not rotated.

### PR C: explicit inactive-project deletion

Only a user can initiate deletion, and only for stopped, completed, or failed projects
whose five role Turns are idle. A second confirmation precedes one bounded transaction
covering exactly the five role Threads, project attachments, the project Registry entry,
and that project's local cache. No background deletion or general recovery system is
allowed; a minimal deletion transaction record may protect this irreversible action.

## 3. Live Houdini acceptance

Before release, the current Launcher and Bridge must be started normally against the
supported Houdini installation. Acceptance requires a visible Scene Viewer single-frame
capture produced by `SceneViewer.flipbook`, a real PNG below
`<project-root>/.runtime/cache/screenshots`, actual image content delivered to Visual
Review, and explicit `VIEWPORT_CAPTURE_UNAVAILABLE` on failure. Record the active
Houdini build, PID/session identity, exact output path, PNG dimensions/hash, and the
Visual Review event that consumed the image. Do not save a HIP merely for acceptance.

## 4. Release and tag

PR #2 remains Draft until its current baseline and live acceptance are complete. It is
not merged and no tag or GitHub Release is created during baseline repair. After the
three required follow-up PRs and release-candidate validation, the approved branch is
merged to `main`; `v0.2.0-rc.1` is created on that `main` commit, RC acceptance runs,
and `v0.2.0` is created on the same verified `main` commit only after user confirmation.
